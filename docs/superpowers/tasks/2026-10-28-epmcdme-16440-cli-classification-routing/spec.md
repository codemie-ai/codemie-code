# Spec: CLI classification evidence and project routing (EPMCDME-16440, cli-classification-routing) - rev 4

Scope: codemie-code only; base fd7d2ace. Paths under `src/`; `spool/` = `providers/plugins/sso/proxy/plugins/otlp-spool/`. Contract: backend `cli-analytics-events.md` plus backend source (`session_binding.py` `check_boundary`, `otlp.py`, `ingestor.py` `_otlp_result`, `cli_analytics_ingest_route.py`, `cli_analytics_project_gate.py` `resolve_session`, `session_purge.py`); MR !4652 unmerged, so no integration claim. The backend re-derives the class and its session binding is immutable; the client value is advisory. #707/#710/#711/#667 are dependencies, not scope. Backend routing is not changed by this child.

## Invariants

- I1 No best-effort proof. A range is sent in evidence mode only if a structural reader proves every record carries the one session id and a project consistent with the stamp. Unproven = held with a reason; bytes are never rewritten.
- I2 Fail closed. A session whose records carry the evidence marker (item 7) and lack a valid durable evidence record, a matching backend identity, or a readable body is held. It never falls through to env/pin/config or to an evidence-free send.
- I3 The server binding of a session id is immutable (owner, project, class) and, with the backend default `CLI_ANALYTICS_SESSION_RETENTION_DAYS=0`, retained indefinitely; it is distinct from the bounded lifetime of the retained local metadata. While a local record exists, spool cleanup, daemon restart, `--resume` and expiry never authorize a change of project, organization or routing for that id. Local eviction does not prove a fresh server session: after eviction the backend binding still decides and nothing silently changes the stored owner, project or class.
- I4 Provenance is explicit, not inferred from absence.
- I5 A known Personal verdict is never forwarded stripped of evidence, whatever the policy or capability state.
- I6 Nothing is sent that commits a session's backend lifetime before its metadata exists. Verified in the backend: any evidence header, including `X-CodeMie-Session-Id` alone, makes an evidence request (`EVIDENCE_HEADERS`, `IngestRoute`); `resolve_session` then binds a destination, and a later Personal-derived request on a session anchored to a shared project is discarded `session_project_conflict`.

## Design

**1. Durable evidence record (stamp).** `OtlpAgentAdapter.processOtlpEvent` creates, before spooling anything, a record next to `session-project-pin.ts` (dir via `getCodemiePath`, mode 0600), keyed by sha256(`api_identity`, `owner_hash`, sessionId). Fields: `schema`, `launch_mode`, `routed_via_codemie`, `organization`, `project`, `project_source` (`linked_folder|profile|none`), `repo_key`, `api_identity`, `owner_hash`, `profile` (diagnostic), `created`, `last_used`. `api_identity` is the canonical backend API identity from one shared function used by hook, forwarder and caches: scheme, lowercased host, port (default dropped), normalized path including the base path, with userinfo, query and fragment removed; an unparsable URL fails closed. `owner_hash` = sha256 of the lowercased signed-in email. Publication is atomic: temp file, `fs.link` to the final name (EEXIST = lost the race; falls back to `wx` plus a bounded read retry where link is unsupported); the loser reads the winner back (up to 3 short retries). The hook never unlinks or repairs a record. If creation or readback fails, or the file at the key is corrupt, of another `schema`, or its stored fields differ from the key, the hook does not enqueue the event (logs a reason) and uses no fallback project. `resolveProjectName` reads the record first, then env/pin/config (the #707 pin path unchanged), so event project, spool binding and headers agree. Nothing is added to event bodies (nothing for #710 `UNMASKED_FIELD_KEYS`).

**2. Launch mode and routing.** `launch_mode` (`CODEMIE_SESSION_ID`; set for every managed provider, `BaseAgentAdapter.ts:555`) selects only the project rule (managed: profile project wins, D2). Routing proof concerns the model route only and is kept separate from the analytics destination. Three URL roles exist and may all differ: the model gateway/upstream (`CODEMIE_BASE_URL` before `setupProxy`, preserved as `CODEMIE_TARGET_API_URL`, passed as `targetApiUrl` by `buildProxyConfig`; `syncCodeMieUrl` comes separately from `CODEMIE_URL`), the local proxy (`setupProxy` rewrites `CODEMIE_BASE_URL` to the loopback proxy URL, `BaseAgentAdapter.ts:1081-1084`), and the analytics backend (`forwarder.resolveBaseUrl`: daemon `targetUrl`/`url`, which is what `api_identity` names). No rule requires the model upstream to equal or prefix the analytics backend URL, and no hostname-only inference is used. The effective Anthropic endpoint is the `~/.claude/settings.json` env value if set, else the process env (`claude.plugin.ts:368-403`).
- Managed: `routed_via_codemie` is true only if the proxy ran under the actual provider/auth setup (`shouldUseProxy`: sso/jwt auth and proxy enabled), `CODEMIE_TARGET_API_URL` is set, the effective endpoint equals the proven local proxy URL (`CODEMIE_BASE_URL`), and the preserved model target is validated against the configured provider/integration (the profile/integration model base URL and `CODEMIE_INTEGRATION_ID`), not against the analytics backend. A direct managed provider (anthropic-subscription, bedrock, ollama, litellm without the proxy) or a settings.json override away from the local proxy is not routed.
- Native: evidence is derived from the actual configured model route (effective endpoint compared by scheme, host, port and path prefix with the model gateway of the signed-in CodeMie profile/integration, or the gateway URL the connector wrote), never from `api_identity`. A positively direct route (empty/first-party Anthropic, Bedrock, Vertex per `session-env-fields.ts`) is `routed=false` and classifies normally. If proof is unavailable (an unmatched or unreadable endpoint) the record stores `routed=false` with `routing_proof: unproven`, and `classify` returns `unknown` for it, never `personal` (local diagnostic basis `routing_unproven`; the sent value stays the 4-value enum and the D7 bases for proven inputs are unchanged).

**3. Organization.** Key `oauthAccount.organizationName` only, from `$CLAUDE_CONFIG_DIR/.claude.json` when set (no fallback to the home file), else `~/.claude.json`; via `readJsonFile`; non-empty trimmed string, 256 cap, else none; never logged. Placement confirmed by a key-names-only probe at plan time.

**4. Project and repository key.** `.codemie` `codeMieProject` beats a global profile for native (`resolveProfileWorkspace`, `utils/config.ts:233`; `linked_folder`), else profile, else none; managed keeps the profile project. The backend `host[:port]/path` key (host lowercased, path case kept, credentials/scheme/`.git`/trailing `/`/default ports 22,443,80 stripped, `[addr]` IPv6; `git@h:8443/a/b` is `h/8443/a/b`, https `:8443` is `h:8443/a/b`) is built beside `parseGitRemoteUrl`; event `repo_remote` untouched.

**5. Classification and caches.** Pure `classify(evidence, policy)` (D7) with the `decide(result) -> forward|suppress|withhold` seam for #711 (no consumer: indeterminate sent as `unknown`). Policy and capability share one file per namespace sha256(`api_identity`, `owner_hash`, profile when the daemon state records it); a cache whose stored identity differs is ignored. Policy usable 24h, 5 min retry backoff; `capability` is `evidence|legacy|unknown`; `legacy` only from an authenticated 404, re-probed after 1h; 401/403/302/5xx/timeouts/non-JSON leave it `unknown`. Sticky verdict (I5): the first determinate `personal` result is persisted in a per-session verdict file with the same key and retention as the record (atomic replace). While no usable policy exists a sticky Personal session is sent only as a full evidence request if the backend is evidence-capable, else held `personal_not_forwardable`; a fresh usable policy may replace it. Hold/loss reasons stay distinct: `classification_unresolved`, `personal_not_forwardable`, `stamp_invalid`, `stamp_pending`, `evidence_capacity`, `session_mismatch`, `session_id_absent`, `project_conflict`, `otlp_unparseable`, `no_evidence_timeout`; #711 opt-out is its own.

**6. Structural proof and request shaping.** No protobuf library exists in `src/` (checked), so add one small bounded reader, no framework: it walks only the needed fields and skips all others by wire type, with declared lengths checked and fixed schema depth. It mirrors the backend decoders: a log's session id is `session.id`, else `session_id`; spans and data points use `session.id` only; resource attributes are not a session source; `codemie_project_name` is noted on record, span, data-point and resource attributes. Field numbers are pinned from opentelemetry-proto and checked by real-encoder fixtures at plan time. Rules:
- Concatenated spool records are legal (repeated top-level field 1); treated as one request.
- Backend `check_boundary` fails the whole request on any `""` or different id. So per record and per hook line the id must be a non-empty string equal to the spool session; absent = `session_id_absent` (empty hook ids are held too); non-string, duplicated with different values, or `session.id`/`session_id` contradiction = `session_mismatch`. A lookalike id in a body or text never counts; a nested attribute is found.
- Any project value (record or resource) must equal the record's project case-insensitively; a value when the record has none, or two different values = `project_conflict`. Absent is fine.
- Truncated, malformed or over-limit input (snapshot bounded by 5,242,880 bytes; at most 256 attributes read per record) = `otlp_unparseable`. Hook NDJSON lines that do not parse are skipped as today.
- Verified-prefix send: slice at top-level resource-entry (OTLP) or line (hooks) boundaries; the longest verified prefix is sent byte-for-byte and the cursor advances only for its acknowledged bytes; the rest is held with the reason. A head-of-line hold ends at the existing spool retention bound by recording loss with that reason, never silently.
- Evidence headers: Session-Id, Routed-Via-CodeMie, Organization (if known), Subscription-Type, Policy-Version, Project-Source and Project (only if a project exists), Repo-Remote. No project: no Project headers; the session is not discarded locally.

**7. Provenance and unstamped sessions.** Each hook record spooled by this CLI carries `evidence_v: 1` in the spool envelope (not the event body). Records without it are genuine pre-upgrade and follow today's legacy path (legacy request: no Session-Id or evidence header), counted `unstamped_legacy`, as does any session under `legacy` capability with no sticky Personal verdict. Marked records need a valid record found by the forwarder's own key (else `stamp_invalid`, held). OTLP-only sessions (no hook, no marker): a spool session older than a one-time `epoch.json` (atomic, written at first run of this version) is pre-upgrade legacy. A newer one on an evidence-capable backend is HELD with reason `stamp_pending` until a valid record appears, then sent normally. There is no timer-send (I6): if no record appears within the existing spool retention bound, the range is dropped with the visible loss reason `no_evidence_timeout` (distinct from opt-out, no-project and `classification_unresolved`). Failures never become legacy forwarding.

**8. Lifetime, cleanup, resume (I3).** The spool may be drained, ended and swept, but the evidence record and verdict file are not spool state: cleanup removes only pending byte files and cursors, never the record. Local retention is a bounded client policy, not the backend lifetime: backend raw retention defaults to 90 days (`CLI_ANALYTICS_RAW_RETENTION_DAYS`) but the per-session binding is retained indefinitely by default (`CLI_ANALYTICS_SESSION_RETENTION_DAYS=0`, `config.py:220-225`; `purge_idle_sessions` purges whole sessions only when that setting is above 0). A record is evictable after 90 days idle (`last_used`, touched at most once per day by hook or forwarder use; env knob read lazily in `spool-config.ts`), and the store is capped at 20,000 files (each under 1 KB), oldest `last_used` first. Neither equals nor aligns with the backend lifetime. A record or sticky verdict is never evicted while its pending spool (unsent or held ranges) still relies on it; if the cap prevents safe retention, new sessions are HELD with `evidence_capacity` (visible), and existing pending privacy state is never silently erased. `--resume` reuses Claude's session id (the pin comment in `session-project-pin.ts` already counts on it), the CLI cannot mint a new one, so a new local lifetime exists only when the key has no record. A resume after sweep/restart with a record present reuses its frozen evidence even if config, project, organization or routing changed; the changed values are ignored for that id, not re-sent. A corrupt record or context mismatch at the key is held `stamp_invalid` until retention evicts it, never re-stamped. After eviction a re-stamp for an old id is allowed locally, but the backend's immutable binding decides: the batch is stored under the bound destination and type, and a Personal request on a shared anchor is discarded `session_project_conflict` and recorded from the response outcome, never an accepted shared send. Sticky-Personal and capability-loss protection (I5) apply to any retained verdict. A genuinely new session id has no record and is stamped fresh. Daemon restart re-reads records, verdicts and the cache; a missing record for marked records is `stamp_invalid`.

**9. Single response consumer** (accepted): one bounded body read in `send()`; hooks JSON and OTLP `partial_success` (protobuf/JSON) decoded; complete rejection final, partial recorded and advanced, 409 refresh/re-classify/resend once, 503 and other failures retain, hooks never acknowledge OTLP; #707's `warnOnBackendDrop` replaced.

## Acceptance criteria (unit; `npx vitest run --project unit`, `npm run typecheck`)

AC1 Routed and direct fixtures in both launch modes x D7 cases x scopes (user, project-in-allowlist, project-outside = nothing stamped); routed true only on positive evidence, never overridden. Fixtures name three separate hosts: model gateway (`llm-gateway.example.com`), local proxy (loopback), analytics backend (`analytics.example.com`), with the gateway host different from the analytics host. Cases: managed routed (proxy ran, effective endpoint = local proxy, target validated against the provider/integration); managed direct subscription (anthropic-subscription/bedrock/ollama, no proxy: not routed); managed with a settings.json override away from the local proxy (not routed); native with the configured gateway (routed); native positively direct (not routed, classifies normally); native with an unmatched endpoint (`routing_proof: unproven`: routed=false and `unknown`, never `personal`); a model gateway host equal to or unrelated to the analytics host changes nothing.
AC2 Known org, not routed, no usable policy: unknown + indeterminate + `policy_unavailable`, never personal; routed with no policy: determinate codemie.
AC3 `withhold` leaves the session unsent and unmoved and re-decides after refresh; no consumer forwards `unknown`; past retention records `classification_unresolved`, distinct from opt-out and no-project loss.
AC4 409 `stale_policy` refreshes, re-classifies, re-decides and resends once without deleting; a failed refresh keeps the spool.
AC5 Hooks discard and OTLP complete rejection (protobuf and JSON) advance exactly their range with the real reason; partial_success with another message is recorded and advanced once; 503/5xx retain; hooks never acknowledge an OTLP stream.
AC6 Unreadable, missing, wrong-type or oversized organization sends no header; a valid one sends only the trimmed name; `CLAUDE_CONFIG_DIR` set/unset read the right file; no value in logs.
AC7 A `.codemie` link beats a global profile (native, `linked_folder`); managed keeps the profile project.
AC8 No project: sent without Project headers and not discarded locally.
AC9 Project change mid-session keeps record, events and headers; a first-sendable pin never overrides them.
AC10 Reader: id nested in attributes of a log, a span and each metric kind is found; a lookalike id in a body/text is ignored; mixed ids, an absent id on any record or hook line, `session.id`/`session_id` contradiction, non-string value, resource-only `session.id`, a project conflict on record or resource, and truncated/malformed/oversized input each hold with the named reason; a valid concatenated multi-record stream is sent unchanged; a poisoned tail sends the verified prefix and holds the rest; sent slices are byte-identical to the input.
AC11 Policy/capability cache is isolated per `api_identity` (including base path), owner and profile; outage and expiry give indeterminate; authenticated 404 gives legacy and recovers after re-probe; 401/5xx/proxy HTML never give legacy.
AC12 Repo-key parity table with the contract examples (scp, ssh, https, default ports dropped, `:8443` kept, path case kept, host lowercased, trailing `/`, `.git`, credentials, IPv6); no raw remote or credential in headers, record or logs.
AC13 #702 scopes and owner resolution unchanged (existing allowlist/identity tests pass).
AC14 Record create/read/corrupt/foreign-identity failures enqueue no event with a divergent project; marked records without a valid record are held, never sent evidence-free; unmarked pre-upgrade records follow legacy; two deployments sharing an origin with different base paths share no record or cache; no userinfo/query token in any key.
AC15 Concurrent creators converge on one winner; hooks never unlink; a record older than 24h on a live session is not rebuilt.
AC16 Sticky Personal stays protected through policy expiry, 404 and `unknown` capability (full evidence or held `personal_not_forwardable`, never stripped); no verdict on an old backend keeps legacy.
AC17 New OTLP-only session without a record on an evidence-capable backend: nothing is sent (no Session-Id-only request), reason `stamp_pending`; when a record appears it is sent with full evidence; if none appears within the spool retention bound it is dropped as `no_evidence_timeout`; a later Personal stamp is never acknowledged under an earlier shared destination; pre-epoch OTLP-only stays legacy.
AC18 Drain/end -> sweep -> daemon restart -> resume with the SAME session id and changed project, organization and routing: the original record is reused and the new values are not sent; sweep removes no record; a corrupt record or key mismatch is held `stamp_invalid`, never re-stamped. A genuinely new session id is stamped fresh. Retention (client policy only): a record idle under 90 days survives; one past 90 days idle or beyond the 20,000-file cap (oldest first) is evictable only if no pending spool relies on it; if the cap would force erasing such state, new sessions are held `evidence_capacity` and pending state stays. Post-eviction fixture: record evicted -> same id resumed with changed config -> a local re-stamp is allowed, the backend's immutable binding decides (stored under the bound destination/type), a Personal request on a shared anchor surfaces as a recorded `session_project_conflict` and is never an accepted shared send, sticky-Personal and capability-loss protection hold for any retained verdict, and the loss stays visible.

## Non-goals

- Opt-out/suppression (#711), masking (#710), tracking-scope redesign, profile commands (#667).
- Backend changes or routing changes, UI, Jira, push/MR; merging or cherry-picking open PRs; any combined-integration claim (#707, !4652).
- Reading Claude credentials or identity beyond the organization name; new event fields; changing event `repo_remote`; minting new session ids.
- A general protobuf/OTLP framework, re-encoding payload bytes, splitting inside a resource entry, de-duplicating codemie-claude `/v1/metrics`.

## Landing order

Either order works: `send()` replaces `warnOnBackendDrop`; the record wins over a pin; #711 plugs into `decide`. Expected textual conflicts: `forwarder.ts`, `session-project.ts`, `spool-io.ts`, `config.ts`, `OtlpAgentAdapter.ts`.
