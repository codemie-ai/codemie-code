# Plan: stop Bedrock settings from silently bypassing the CodeMie gateway

Spec: `spec.md` (same folder); research: `technical-analysis.md`. Commit per task using the repository's existing convention. No ticket ID, link or customer name in any file, comment or commit. ESM, `.js` import suffixes, `@/` alias, `logger` (never log setting values), `getCodemiePath()`, no `any`. Tests: Vitest, co-located `__tests__`, real tmp dirs with injected platform/env/cwd/prompt/runners, never real user files; dynamic import after mocks (`.ai-run/guides/testing/testing-patterns.md`).

New module family: `src/agents/plugins/claude/cloud-provider-conflict/` (tests in its `__tests__/`). Layering is CLI -> registry -> plugin: nothing in this family imports from `src/cli/commands/proxy/connectors/` (or any `src/cli/` path), statically or dynamically. Callers in the CLI layer (`connect-orchestrator.ts`) resolve the Desktop and VS Code paths and pass them in, so there is no import cycle to manage. T3 asserts the family has no `cli/` import. In the other direction, core and the CLI never import this family either: they call the optional adapter hook `AgentAdapter.checkProviderSettings` (T8), which the Claude adapters implement.

Stop contract: nothing in this family calls `process.exit`. The gate returns a `GateOutcome`: `{kind: 'proceed', token}` or `{kind: 'stop', reason: 'cancel'|'managed'|'unknown'|'non-interactive', guidance}`; the adapter hook turns it into the core `ProviderSettingsCheckOutcome` (`proceed` with `apply()`, or `stop` with `guidance`). The shared core helper `runProviderSettingsCheck(adapter, input, onStop)` (`src/agents/core/provider-settings-check.ts`) turns a stop into the command's exit: `onStop: 'exit'` (`AgentCLI`, `install`) prints the guidance on stderr and calls `process.exit(1)`; `onStop: 'throw'` (`proxy connect`) throws `ConfigurationError(guidance)`, which the orchestrator's existing `printProxyError` prints and exits 1 with.

## T3 — Managed readers (plist) and resolver
Files: `src/agents/core/claude-settings.ts` (add `readManagedPlist(run, exists)`, `managedPlistPaths(username)` and `readManagedPlists(run, exists)`); `cloud-provider-conflict/resolver.ts` (new).
Readers: macOS plists in Claude Code's order, per-user `/Library/Managed Preferences/<user>/com.anthropic.claudecode.plist` (left out when the login name is empty or not a single folder name) then device-level, each through `/usr/bin/plutil -convert json -o - -- <file>`; a missing plist = absent; read/parse failure of an existing file = unknown. `plutil` that cannot start, 2-3 s timeout, or unparseable output = unknown. The Windows registry is not read. Runners are injected (default wraps `src/utils/exec.ts`).
Resolver: `resolveProviderConflict({provider, flow, paths, platform, env, cwd, runners})` returns per-layer `{path, scope, editable, state, inEffect, keyNames}` and verdict `none|conflict-editable|conflict-managed|unknown`. `paths` is the caller-supplied input for every file the resolver reads, including the connect-flow extras `desktopApplied?: string`, `desktopManaged?: string | null` and `vscodeSettings?: string[]` (stable and Insiders, editions that do not exist omitted); the resolver never computes these itself and imports nothing from `src/cli/`. Flow source table per spec (`claude-agent`/`install` read project layers and shell env; `connect-desktop`/`connect-vscode` do not; Desktop applied file and VS Code settings come from `paths`). Highest layer defining the flag decides (`flagState`); unreadable decisive layer, unknown spelling, unparseable Desktop applied file = `unknown`; malformed Claude Code file is skipped with a warning naming analytics attribution. Parallel reads, elapsed time at `logger.debug`.
VS Code source (not `readSettingsLayer`): each `vscodeSettings` path is read with `jsonc-parser` `parse(raw, errors, {allowTrailingComma: true})`, the same options as `vscode-claude-code.ts:65-94`, so `//` and `/* */` comments and trailing commas are valid and never count as malformed. Only a genuine JSONC parse error (`errors.length > 0`) or a non-object root is "can't tell" (`unknown`, guidance names the file); an empty file, an absent file, or a file without the key is absent. `claudeCode.environmentVariables` is an array of `{ name, value }` entries (as `isEnvVarEntry`, `vscode-claude-code.ts:96`): the resolver looks for an entry whose `name` is `CLAUDE_CODE_USE_BEDROCK` (last one wins) and feeds its `value` to `flagState`; non-object entries are ignored, a non-array value counts as no entries (as the connector does), `keyNames` lists entry names only. It never looks for an object key of that name. Precedence: the extension passes these as process env, so VS Code entries rank at process-env level, below every Claude settings layer (managed, project, user); a VS Code flag decides only when no Claude settings file defines the flag, and each edition is its own source.
Test-first: yes — `resolver.test.ts`: per source (user, local, project, managed file/drop-in/per-user and device plist, shell env, Desktop via injected `paths`); precedence; split-layer case; the "absent" outcome per platform (no plist, no managed files, no command started on Windows) gives `none`; runner failure/timeout/unparseable/unreadable plist gives `unknown`; malformed Claude file skipped with warning; no setting value appears in any returned diagnostic; VS Code: a file with a `//` comment and trailing comma plus a Bedrock entry gives `conflict-editable` (not skipped), a real parse error gives `unknown`, a flag as a top-level object key is not detected, a Bedrock VS Code entry is overridden by a user-settings layer setting the flag off (and decides when no Claude file defines it), a stable and an Insiders file are both read; a source-text check that no file in `cloud-provider-conflict/` imports a `cli/` path.

## T5 — Switcher (backup, manifest, strip, restore)
File: `cloud-provider-conflict/switcher.ts` (new).
`applySwitch(plan, deps)`: re-resolve; read each file once; create `getCodemiePath('backups','bedrock-switch-<timestamp>')` with non-recursive `mkdir` (EEXIST: retry with random suffix), 0700; on Windows `restrictToCurrentWindowsUser` (`cloud-provider-conflict/backup-access.ts`) replaces its inherited access rules with full control for the current SID before any file is written, and a failure only warns; write `manifest.json` first (version, per copy original path and file kind `claude-json | vscode-jsonc | desktop-applied`, no values); copies 0600 (explicit `chmod`), verified before any strip. Strip per spec for Claude JSON files: flag-scoped keys only from layers that set the flag, Bedrock-ID model keys (`model`, `ANTHROPIC_MODEL`, `ANTHROPIC_DEFAULT_*_MODEL`, `ANTHROPIC_SMALL_FAST_MODEL`, `CLAUDE_CODE_SUBAGENT_MODEL`, matching `availableModels` entries) from every editable layer read; derive output from the backed-up bytes; JSONC-preserving edits via `jsonc-parser` `modify`. Atomic write is a small local helper in this module (resolve the real path, write the temp file beside it, rename; `renameReplacing` retries EPERM/EBUSY/EACCES on Windows after 50/100/200/400/800 ms and re-runs the change check before each attempt); do not import `writeAtomically` from `connectors/vscode.js`, which would point the plugin at the CLI layer. Abort and restore already-written files if mtime or size changed before rename or a later write fails, error names the backup folder. Desktop applied file: back up only; no strip here (T7). Prints folder, undo sentence, credential/deletion notice, managed-wins note.
VS Code settings strip operates on the `claudeCode.environmentVariables` array only: remove whole `{ name, value }` array entries (never object keys, in that file or elsewhere in it) — the `CLAUDE_CODE_USE_BEDROCK` entry itself, the descriptor's flag-scoped env names (AWS keys, region, profile, bearer token) when that file has the flag entry, and entries whose `name` is a Bedrock model env key and whose `value` passes `isModelId`. Edits use `modify(raw, ['claudeCode.environmentVariables', index], undefined, {formattingOptions})` applied from the highest index down (formatting detected as in `vscode-claude-code.ts:107-113`), so comments, trailing commas and formatting survive; other entries (gateway base URL, token, user variables, non-object entries) and every other setting are untouched; an emptied array stays `[]`.
Test-first: yes — `switcher.test.ts`: manifest first and verified copies; modes 0700/0600 on POSIX; Windows folder access restricted before the first write, a failed restriction warns and the switch continues, no restriction elsewhere; `renameReplacing` retry, give-up, no-retry and changed-while-waiting cases, and one locked attempt through `writeFileAtomicDefault`; `backup-access.test.ts` for the `whoami`/`icacls` calls and their failures; EEXIST retry never reuses a folder; unrelated keys and non-Bedrock model values survive; JSONC comments/formatting kept; VS Code case: array with flag, AWS-key and Bedrock-model entries plus a gateway entry and a `//` comment, only the Bedrock entries vanish as whole entries, the rest is byte-preserved, a top-level `CLAUDE_CODE_USE_BEDROCK` object key is never touched, a non-Bedrock `ANTHROPIC_MODEL` entry survives; symlinked settings stay symlinks; changed-file abort restores; mid-switch write failure restores and names the folder; backup failure changes nothing.

## Constraint map (negative-constraint pass)
- No docs, CLI help or restore command: none planned. No per-session `--settings`: none (T5 edits files only). Vertex/Foundry: descriptor only, Bedrock filled (T1).
- Start-up migrations ungated; `readClaudeSettingsEnv` semantics, `detectSettingsConflict` and OTLP `.codemie-backup` unchanged: T2 folds with today's mapping; T8-T10 leave the others alone.

- No setting values in logs, guidance or manifest: T3-T5.
