# EPMCDME-16321 Implementation Plan

**Goal:** a hook cold start restarts the proxy daemon on the profile `proxy connect` recorded (`~/.codemie/proxy-connection.json`), never on the cwd's active profile, warns on missing SSO credentials and still starts so the daemon holds the port (#755), and names the profile in every log line.

**Rules:** do not commit, push or branch; the user reviews the working tree. Per task run only that task's test files (`npx vitest run <file>`); the whole-suite gate belongs to qa-gates. Do not touch `disconnect-orchestrator.ts`, `.codemie/codemie-cli.config.json`, `proxy-daemon.json` semantics, `identity-fields.ts` or the plugins' `ensureProxyAuth`. The record is never deleted by any code. Types: reuse `DaemonState`, `SpawnOptions`, `DaemonIdentity`, `RequestedDaemonConfig`; add only two named interfaces (`ClientIdentity`, `ProxyConnectionRecord`, Task 1); no unions, string-literal aliases or inline `Pick`/intersection signatures; `clientType` stays a plain `string` and `telemetryMode` keeps its existing type via `DaemonState['telemetryMode']`. Repo rules: `.js` import extensions, `@/` alias, `getCodemiePath`, `logger.*` (never `console.*`) on hook paths, `sanitizeLogArgs`, explicit return types, no `any`.

**Decisions taken here (review findings):**
- AR-1 (user decision): the same-named local profile is honoured "as today": `ConfigLoader.load(process.cwd(), { name: record.profile })` with the hook's exact cwd. No walk-up lookup and no `CLAUDE_PROJECT_DIR` handling. Consequence: a hook running in a subfolder of a repo that defines the profile locally falls back to the global profile (as today); a repo-only profile restarts only when the hook's cwd is the repo root, elsewhere it is "not found". Scope (global or local) and existence come from the loader (`loadLocalConfigProfile(cwd, name)` / `loadGlobalConfigProfile(name)`, legacy local config included), not `listProfiles`.
- Open PR #741 changes `identity-fields.ts`, the hook auth profile and the three OTLP plugins' `ensureProxyAuth`; no task here touches those files.
- AR-2: `proxy connect` writes the record once, after at least one target succeeded (not at readiness), so a rolled-back connect leaves it untouched. `writeConnectionRecord` refuses a state whose profile or client type differs from the call's request (warn naming both). Whether to write is a plain boolean the caller decides: `SpawnOptions.writeRecord` (default true). `proxy start`/`restartStopped` pass `Boolean(opts.profile) || !(await readConnectionRecord())`; `restartRunning` passes `false` and writes after its port check. A write failure only warns. Concurrent writers: per-process tmp name, atomic rename, last identical-identity writer wins. `restartStopped` and `proxy start` without `--profile` still load the cwd profile (documented, not changed).
- AR-3: every skip reason is logged at warn with the profile name; one try/catch tags any throw with it before rethrowing.
- AR-4: a skipped cold start leaves `forwardOtlpEventsToSpool` false, so cursor-carrying handlers get `finalize(false)` and re-send later; per-event hooks and a SessionEnd in the down window are lost. Tested (Task 7) and documented (Task 8).
- AR-7 (user decision, rebase onto #755): missing or expired SSO credentials no longer skip the cold start. `assertSsoCredentials` stays, but on the hook path its result is only a warn naming the profile (and scope); the hook spawns on the recorded profile and the daemon holds the port with the 401 listener until login. This replaces the fail-fast (spec decision on credentials, AC2) because #755 makes a credential-less daemon start quickly and hold the port, so skipping would only leave port 4001 and the Claude Code endpoint unprotected. The cold start also keeps #755's port and endpoint handling (`readConfiguredOtlpPort`, `refreshClaudeCodeOtlpEndpoint`). The cold start moved to `otlp-cold-start.ts` (review finding CR-003), so Task 4's `connect-orchestrator.ts` line references now point to that module.
- Review notes adopted: `version: 1` and merge-write, seeding logged at info, liveness re-check before `ensureDaemon`, spawn arguments and `requested` built once from the record and the loaded config. The project is not recorded (decision CR-003): the daemon's project is `config.codeMieProject`.

## Task 1: Record I/O, writer and seeding (`src/cli/commands/proxy/daemon-manager.ts`)
Add next to `DaemonState` (:9-31) two exported interfaces, and next to `DEFAULT_STATE_FILE` (:33) `CONNECTION_FILE = getCodemiePath('proxy-connection.json')`:
```ts
/** The identity fields a daemon, a spawn request and a record all share. */
export interface ClientIdentity { clientType?: string; telemetryMode?: DaemonState['telemetryMode'] }
/** Identity of the last daemon start, persisted in proxy-connection.json (no secrets, URL, model or provider). */
export interface ProxyConnectionRecord extends ClientIdentity { version: 1; profile: string; updatedAt: string }
```
`DaemonState` and `SpawnOptions` already satisfy `ClientIdentity` structurally. Functions:
```ts
readConnectionRecord(file?: string): Promise<ProxyConnectionRecord | null>
writeConnectionRecord(state: DaemonState, profile: string, clientType?: string, file?: string): Promise<boolean>
seedConnectionRecord(state: DaemonState, file?: string): Promise<void>
```
Reader: `null` when the file is missing; a JSON object with a non-empty string `profile` is the only valid shape, anything else (`null`, an array, no/empty profile) returns `null` after a warn giving the reason; a `clientType` that is not a string or a `telemetryMode` outside the values `DaemonState` allows is dropped with a warn naming the field. Writer (`profile`/`clientType` are what the call requested): returns `false` with a warn naming both sides when `state.profile !== profile` or, when `clientType` is given, `state.clientType !== clientType` (daemon states always persist the derived client type, `src/bin/proxy-daemon.ts:90`); merge-writes over the existing JSON object (unknown fields kept, identity fields replaced wholesale) with `version: 1` and `updatedAt`; tmp file `<file>.<pid>.tmp` then `rename`; any I/O error is a warn (`sanitizeLogArgs`) and `false`, never a throw; `true` when written. `seedConnectionRecord` does nothing when `readConnectionRecord()` is non-null, else `writeConnectionRecord(state, state.profile, state.clientType)` and, only on `true`, logs info `Seeding proxy-connection.json from the running daemon (profile: X)`.
Test-first: yes — `daemon-manager.test.ts` (add `getCodemiePath` to its `paths.js` mock, :14-22; clean the record in `afterEach`): reader returns null for a missing file, `null`, an array, a missing or empty profile (warn with the reason) and drops a wrongly typed field with a warn; writer returns true and merges while keeping an unknown field, returns false with a warn naming both on a profile or client-type mismatch, returns false without throwing on an unwritable path, two concurrent writers leave a parseable file; seed writes once, logs info, and leaves an existing valid record alone.
