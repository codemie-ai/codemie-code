# Shell Completions

`codemie completion <bash|zsh|fish>` prints a static completion script to stdout. The script is generated from the CLI's own command tree, so it lists the real commands and options of the installed version.

Startup work (migrations, update check, what's-new) is skipped for `codemie completion`. Output is one stdout write; errors go to stderr with exit code 1.

## What gets completed

- Commands and subcommands at every level. Hidden commands and options are never offered.
- Options, including the root options (`--task`, `-V`, `--version`). The CLI accepts root options after a subcommand (for example `codemie list --version`), so completion offers them at every node.
- Option values: the declared choices when an option has them, file paths only for path-valued options, and nothing otherwise.
- bash and zsh offer commands and options at every position. fish offers options only once the typed word starts with `-`.
- Alias handling exists in the generator but is forward-looking: the CLI has no real command aliases today.

## Keeping the script current

Each script starts with a header such as `# codemie completion bash — generated by codemie vX.Y.Z` (zsh: on line 2, after `#compdef codemie`). The version stamp lets you detect a stale cached file after an upgrade. Regenerate after every `npm i -g @codemieai/code`.

Write the script to a temporary file and then `mv` it into place. Writing directly can leave a partial file if the pipe closes early.

Generating the script starts Node.js and loads the CLI, which takes well under a second on a typical machine (roughly 0.7 s when measured on a WSL2 development machine). That is why the recommended setup is a cached file, not running the command on every shell start.

## Bash

Cached file (recommended; loaded automatically by bash-completion v2):

```bash
mkdir -p ~/.local/share/bash-completion/completions
codemie completion bash > ~/.local/share/bash-completion/completions/codemie.tmp \
  && mv ~/.local/share/bash-completion/completions/codemie.tmp \
        ~/.local/share/bash-completion/completions/codemie
```

Open a new shell afterwards. To try it out in the current shell only:

```bash
source <(codemie completion bash)
```

## Zsh

Save the script as `_codemie` in a directory on `fpath`, then enable `compinit`:

```zsh
mkdir -p ~/.zsh/completions
codemie completion zsh > ~/.zsh/completions/_codemie.tmp \
  && mv ~/.zsh/completions/_codemie.tmp ~/.zsh/completions/_codemie
```

In `~/.zshrc`, before `compinit`:

```zsh
fpath=(~/.zsh/completions $fpath)
autoload -Uz compinit && compinit
```

The script also works when sourced directly (`source <(codemie completion zsh)`, after `compinit`). If completion does not appear after an update, remove `~/.zcompdump*` and start a new shell.

## Fish

```fish
mkdir -p ~/.config/fish/completions
codemie completion fish > ~/.config/fish/completions/codemie.fish.tmp
and mv ~/.config/fish/completions/codemie.fish.tmp ~/.config/fish/completions/codemie.fish
```

Fish loads the file on the next shell start.

## WSL

Run the commands above with the Linux `codemie` (check `type -a codemie`; it should not resolve to `/mnt/c/...`). Keep the completion file in the WSL home directory.
