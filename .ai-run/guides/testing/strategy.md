## Layers

### Unit
- **Framework:** Vitest 4.1.5 (project `unit`), built-in `expect` assertions
- **Location:** `src/**/__tests__/*.test.ts` (co-located with the code under test)
- **Naming:** `<subject>.test.ts`
- **Structure:** nested `describe`/`it`, Arrange-Act-Assert
- **Setup style:** `beforeAll`/`beforeEach` for fixtures; `vi.restoreAllMocks()` in `afterEach`. Static imports bypass `vi.spyOn` — the dynamic-import-after-spy pattern is mandatory (see `.ai-run/guides/testing/testing-patterns.md`)
- **Selectors:** n/a (no UI layer)
- **Abstractions:** none (no page objects; this is a CLI, not a browser app)
- **Support-file paths:** none beyond co-located `__tests__/` directories
- **Run one test:** `npx vitest run <test-file>`
- **Run suite:** `npx vitest run --project unit`

### API/Integration
- **Framework:** Vitest 4.1.5, two sub-tiers in the same runner: project `cli` (shells the built CLI) and project `agent` (live network against the real CodeMie lab backend)
- **Location:** `tests/integration/**/*.test.ts` (files named `agent-*.test.ts` belong to the `agent` project; all others to `cli`)
- **Naming:** `<area>.test.ts` (cli), `agent-<area>.test.ts` (agent)
- **Structure:** nested `describe`/`it`, Arrange-Act-Assert
- **Setup style:** a `createCLIRunner()` helper (`tests/helpers/`) shells the built CLI and asserts on stdout/exit code; `agent` tests gate on `describe.runIf(process.env.SSO_AVAILABLE !== 'false')` and consume the developer's own local SSO session
- **Selectors:** n/a (no UI layer)
- **Abstractions:** `CLIRunner` and `TempWorkspace` test helpers under `tests/helpers/`
- **Support-file paths:** `tests/helpers/`
- **Run one test:** `npx vitest run --project cli -- <test-file>` (cli tier only; no declared single-file template for the agent tier)
- **Run suite:** `npx vitest run --project cli` (cli tier) / `npx vitest run --project agent` (agent tier — never run in CI; needs a live local SSO session)
- **Run suite (verbose):** `npx vitest run --project agent` (the `agent` project is hardcoded in `vitest.config.ts` to the `verbose` reporter — there is no separate flag variant)

No silent/low-noise command variant is declared for any layer in this repository (checked `package.json`, `ci.yml`, `vitest.config.ts`).

## Project conventions

- Full "Running Tests and Validation" section in `CONTRIBUTING.md` (matches `package.json` scripts exactly).
- `tests/README.md` states the project's own target split: Integration 70% / Unit 30%, and documents the `CLIRunner`/`TempWorkspace` helpers.
- `.ai-run/guides/testing/testing-patterns.md` (pre-existing, written independently of this file) covers mocking patterns, lazy-getter overrides, and cross-platform path assertions in depth — read it alongside this file rather than duplicating it here.
- New tests continue citing the originating ticket key in file-header comments and `describe`/`it` names (e.g. `EPMCDME-15411, AC4`), matching the existing convention — this is informal prose, not a structured marker.
- **No ticket references in the factory's own case IDs.** The `// @case <case ID>` traceability comment that every generated test carries is ticket-free (`<slug>_TC_001`) — common approach across repos, independent of the ticket citation above and of `git_conventions` below. Do not add a ticket key to it (PR #783 review).
