This is a CLI tool, not a web app: there is one real "environment" — the CodeMie SSO lab backend that the `agent` Vitest tier talks to over the network. It is never a separate staging/prod split for this repository's own purposes.

## Test accounts

No dedicated test account exists. The `agent` tier runs under whatever SSO session the developer invoking the tests is already logged into locally (via `codemie profile login`) — there are no `MYBOOKS_USER`-style credential variables to set. The tier is gated by `SSO_AVAILABLE` (skipped only when explicitly set to `false`) and never runs in CI.

| Environment | Role | Username var | Password var |
|---|---|---|---|
| lab | developer's own session | n/a | n/a |

## Test data

- **Strategy:** built per run — temp workspaces (`TempWorkspace` helper) and fixtures/mocks created fresh per test; the `agent` tier talks to the live lab backend directly with no seeded dataset.
- **Reset mechanism:** none needed — per-test temp workspaces are created and torn down automatically; nothing persists that would need resetting.
- **Notes:** the `agent` tier is permitted to mutate/consume real state on the lab backend (destructive testing is allowed there).

## Safety

- Environments not marked as permitting destructive testing must be treated as unsafe.
- Credentials are referenced by variable name only. No secret value appears in this file or any artifact this factory produces.
